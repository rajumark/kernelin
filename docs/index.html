01 / TRANSLATE

Kotlin in. WGSL out.
Nothing to hand-write.

A K2 compiler plugin reads your function's IR right after type checking and emits a compute shader. Arrays become storage buffers, Int and Float parameters move into a uniform, and globalId() becomes the GPU thread index. Hover a Kotlin line to see what it became.

        02 / ONE FUNCTION, TWO ENGINES
        
Test it on the CPU.
Ship it to the GPU.

        
A kernel is still a normal Kotlin function. Run it with KernelinCpu in a plain unit test, step through it in the debugger, then send the very same code to the GPU. No second language, no copy that drifts out of sync.

        
    
          
  • KernelinCpu.dispatch runs every thread on one core, great for tests
    • 
          
  • dispatchParallel spreads it across all JVM cores
    • 
          
  • WebGpu.create() runs it on the real GPU from Kotlin/Wasm
    • 
        

        See both runners →

        03 / SAFE BY CONSTRUCTION
        
Errors at compile time,
not on the GPU.

        
If your kernel uses something a GPU can't run (strings, Double, Long, lambdas, recursion, exceptions, nullable types) you get a normal Kotlin compiler error with file, line and a hint. In the IDE and in CI, before anything ships.

        
    
          
  • Clear messages that say what to write instead
    • 
          
  • Every shader validated by naga, and kernels proven equal to Kotlin on a real GPU in CI
    • 
          
  • The manifest tells hosts exactly how to bind buffers
    •

          04 / INSIDE THE COMPILER
          
From .kt to silicon
in one build step.

        

        
Kernelin plugs into the Kotlin compiler as an IR generation extension. It runs before any platform lowering, so loops, &&, ++ and += still have their original shape and map cleanly onto WGSL.

          05 / BENCHMARKS
          
Real numbers,
honestly measured.

        

        
GPU kernel time versus the same Kotlin code on all 10 CPU cores of an Apple M5. Heavy math wins big. Light kernels win only when data stays on the GPU; copying it there and back costs more than the work.

      

      

        

          GPU speedup, data already on the GPU (log scale)
          1× = same as CPU
        

        

        

        

          
MachineApple M5, 10 CPU cores, 8-core GPU. WebGPU in Chromium (Dawn → Metal).

          
MethodGPU: mean of 20 dispatches, median of 5. CPU: KernelinCpu on JDK 21, median of 5 after warmup.

          
CorrectnessGPU output equals the Kotlin CPU output for all 5 kernels (mandelbrot: 99.8% of pixels, float rounding).

        

        

          
Also on Androidmoto g57 power: Adreno 7xx GPU in Chrome 155 vs the same Kotlin on ART, all 8 cores.
